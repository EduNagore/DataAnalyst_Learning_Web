Un asistente genera mejores consultas cuando recibe **contexto**: qué tablas hay, qué significa cada métrica de negocio, un ejemplo y cómo debe responder si no sabe. Y debe recibirlo **sin datos personales**: el esquema, no las filas.

Con las tablas `orders`, `order_items` y `returns` (en `esquemas`), implementa:

1. **`tipo_sql(serie)`** → tipo SQL de una columna.
2. **`construir_prompt(pregunta, esquemas, definiciones, ejemplos, dialecto)`** → prompt con las secciones indicadas en el docstring.
3. **`auditar_prompt(prompt, esquemas, presupuesto_tokens)`** → lista de problemas.

La función `asistente_simulado()` (ya escrita) es un `MockLLM` que responde con el SQL correcto solo si el prompt trae la definición de `ingresos_netos`, y con una consulta ingenua si no la trae: simula lo que ocurre con un modelo real cuando le falta una definición de negocio.

Resultado esperado: el prompt completo ocupa ≈ 260 tokens (≈ 175 sin definiciones ni ejemplos), pasa la auditoría y produce la consulta correcta; sin la definición, el asistente simulado cuenta pedidos en lugar de sumar ingresos netos.
