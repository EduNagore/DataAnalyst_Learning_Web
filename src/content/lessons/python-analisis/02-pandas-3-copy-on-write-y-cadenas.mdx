pandas sigue siendo la biblioteca más usada para análisis en Python y la que entiende casi todo el
ecosistema (statsmodels, scikit-learn, librerías de gráficos). Su versión 3 cambió reglas de fondo
que rompen código antiguo y que, bien entendidas, hacen el código **más seguro y predecible**.

## Intuición

Un `DataFrame` es una tabla en memoria. Hasta pandas 2, a veces dos variables compartían los mismos
datos por debajo y a veces no, y el resultado de modificar una dependía de detalles internos. Eso
causaba el famoso `SettingWithCopyWarning`. La idea de pandas 3 es sencilla: **cada objeto derivado
se comporta como una copia independiente** (aunque por dentro comparta memoria hasta que lo
modifiques, de ahí el nombre _Copy-on-Write_, «copiar al escribir»). Con esa regla, el código es más
fácil de razonar: si modificas `b`, que viene de `a`, `a` no cambia.

## Cómo funciona

### Texto: el dtype `str`

En pandas 3, las columnas de texto tienen por defecto el tipo `str` (antes `object`, una columna de
objetos de Python genéricos). Si tienes PyArrow instalado, `str` lo usa por debajo. Los valores
ausentes siguen siendo `NaN`:

```python
import io
import pandas as pd

df = pd.read_csv(io.StringIO("id,region\n1,Madrid\n2,\n3,Andalucía"))
print(df.dtypes.to_dict())      # {'id': int64, 'region': str}
print(df["region"].isna().tolist())   # [False, True, False]
```

Ventajas prácticas: menos memoria y operaciones de texto más rápidas (en la columna `channel` de
`orders`, 400.000 filas, ocupa 5,6 MB como `str` frente a 25,2 MB como `object`), y errores más
claros: una columna `str` no acepta que le asignes un número por accidente.

### Copy-on-Write

La regla: **un objeto derivado nunca modifica el original**.

```python
a = pd.DataFrame({"x": [1, 2, 3]})
b = a[["x"]]              # b se obtiene de a
b.loc[0, "x"] = 99
print(a["x"].tolist())    # [1, 2, 3]   <- a no cambia
print(b["x"].tolist())    # [99, 2, 3]
```

Consecuencias que te afectan:

- Los arrays obtenidos con `.to_numpy()` o `.values` son de **solo lectura** por defecto; si necesitas
  modificarlos, haz una copia explícita con `.copy()`.
- Los métodos con `inplace=True` ya no aportan ventaja y se desaconsejan; usa la forma funcional
  (`df = df.sort_values(...)`).

<Callout type="warning">
  Copy-on-Write protege los objetos **derivados**, no al objeto que recibe una función. Si una
  función hace `df["nueva"] = 1` sobre el argumento, estás modificando el DataFrame del que llama.
  Dentro de funciones, devuelve una copia con `assign` en vez de modificar el argumento.
</Callout>

### Asignación encadenada: ya no funciona

Antes, `df[df["x"] > 1]["y"] = "Z"` a veces cambiaba `df` y a veces no. En pandas 3 **nunca** cambia
el original, porque `df[df["x"] > 1]` es un objeto derivado. pandas avisa con un
`ChainedAssignmentError`. La forma correcta es una sola operación con `.loc`:

```python
d = pd.DataFrame({"x": [1, 2, 3], "y": ["a", "b", "c"]})

# Mal: modifica una copia temporal y la tira
d[d["x"] > 1]["y"] = "Z"                 # ChainedAssignmentError

# Bien: una sola asignación con .loc
d.loc[d["x"] > 1, "y"] = "Z"
print(d["y"].tolist())                   # ['a', 'Z', 'Z']
```

### Encadenar métodos y `pd.col`

Un análisis legible es una **cadena de métodos**: cada línea hace una transformación y devuelve un
nuevo DataFrame. Dentro de la cadena necesitas referirte al DataFrame «de ese momento»; hasta ahora
se hacía con `lambda`:

```python
df.assign(total=lambda d: d["quantity"] * d["unit_price"])
```

pandas 3 introduce `pd.col()`, una expresión que se evalúa sobre el DataFrame actual:

```python
df.assign(total=pd.col("quantity") * pd.col("unit_price"))
df.loc[pd.col("discount_pct") > 0.2]
```

Hace lo mismo, con menos ruido. Las `lambda` siguen funcionando y son necesarias para lógica más
compleja.

### Fechas y frecuencias

- Al leer o convertir fechas, pandas 3 **infiere la resolución** del dato; por defecto suele ser
  microsegundos (`datetime64[us]`), no nanosegundos como antes. Puede afectar a código que asumía `ns`.
- Los alias de frecuencia antiguos de fin de periodo ya no existen: usa `ME` (fin de mes), `QE` (fin
  de trimestre) y `YE` (fin de año). `resample("M")` lanza un `ValueError`.

```python
orders.set_index("order_date")["order_id"].resample("ME").count()   # pedidos por mes
```

### Unir sin duplicar: `validate`

Un `merge` mal planteado multiplica filas (el fan-out de SQL). pandas permite **declarar la relación
que esperas** y falla si no se cumple:

```python
# Cada línea de pedido pertenece a un pedido: relación muchos-a-uno
lineas.merge(pedidos, on="order_id", validate="many_to_one")
```

Si `pedidos` tuviera `order_id` duplicados (aquí, 1.000 pedidos repetidos por error añaden 2.612
líneas de más), pandas lanza `MergeError: Merge keys are not unique in right dataset`. Es una
aserción gratuita contra el error más caro de un join.

## En la práctica

Ingresos y ticket medio de 2025 por segmento, de principio a fin:

```python
import pandas as pd

R = "public/data/lumen/"
orders = pd.read_parquet(R + "orders.parquet")
items = pd.read_parquet(R + "order_items.parquet")
customers = pd.read_parquet(R + "customers.parquet")

por_segmento = (
    items
    .merge(orders[["order_id", "customer_id", "order_date", "status"]],
           on="order_id", validate="many_to_one")
    .merge(customers[["customer_id", "segment"]],
           on="customer_id", validate="many_to_one")
    .loc[lambda d: (d["status"] != "cancelado") & (d["order_date"].dt.year == 2025)]
    .assign(ingresos=pd.col("quantity") * pd.col("unit_price"))
    .groupby("segment", as_index=False)
    .agg(pedidos=("order_id", "nunique"), ingresos=("ingresos", "sum"))
    .assign(ticket_medio=lambda d: (d["ingresos"] / d["pedidos"]).round(2))
    .sort_values("ingresos", ascending=False)
)
```

| segmento  | pedidos |     ingresos | ticket medio |
| --------- | ------: | -----------: | -----------: |
| habitual  |  60.519 | 18.524.725 € |     306,10 € |
| vip       |  47.226 | 14.461.809 € |     306,23 € |
| ocasional |  32.684 |  9.986.315 € |     305,54 € |
| nuevo     |  21.277 |  6.487.908 € |     304,93 € |

Fíjate en que el ticket medio es casi idéntico entre segmentos (≈ 305 €): la diferencia de ingresos
viene del **número de pedidos**, no del importe por pedido. Esa es la conclusión útil para Marketing.

**Comprueba siempre el resultado con una segunda vía.** La misma consulta en SQL sobre los mismos
datos (con DuckDB sobre los DataFrames) devuelve exactamente las mismas cifras:

```python
import duckdb

duckdb.sql("""
    SELECT c.segment, COUNT(DISTINCT o.order_id) AS pedidos,
           ROUND(SUM(oi.quantity * oi.unit_price)) AS ingresos
    FROM items AS oi
    JOIN orders AS o USING (order_id)
    JOIN customers AS c USING (customer_id)
    WHERE o.status <> 'cancelado' AND year(o.order_date) = 2025
    GROUP BY 1 ORDER BY 3 DESC
""").df()
```

## Trade-offs y cuándo usarlo

- **pandas** es la opción por defecto cuando necesitas el ecosistema (estadística, modelos,
  gráficos) o trabajas con datos que caben cómodamente en memoria.
- Las cadenas de métodos son más legibles y fáciles de depurar (puedes cortar la cadena y mirar un
  paso intermedio), pero una cadena de veinte pasos también es ilegible: parte en funciones con nombre.
- `validate=` añade una comprobación de unicidad; en tablas muy grandes cuesta tiempo, pero casi
  siempre compensa frente a un fan-out silencioso.
- Para datos grandes o transformaciones pesadas, mira Polars o DuckDB (siguientes lecciones).

## Errores comunes

- **Asignación encadenada** (`df[mask]["col"] = valor`): no hace nada en pandas 3. Usa `.loc[mask, "col"]`.
- **Modificar el DataFrame que recibe una función**: el que llama ve el cambio. Devuelve una copia.
- **Unir sin `validate`** y dar por buena una suma inflada por un fan-out.
- **`resample("M")`** u otros alias antiguos: usa `ME`, `QE`, `YE`.
- **Asumir `datetime64[ns]`**: la resolución ahora se infiere; no mezcles resoluciones sin comprobarlo.
- **Contar con `count()` cuando querías `nunique()`**: sobre líneas de pedido, `count` cuenta líneas, no pedidos.
- **No comparar con una segunda fuente**: una cifra que solo sale de una cadena de pandas sin
  contraste es una hipótesis, no un dato.

## Con IA

Los modelos de lenguaje se entrenaron con mucho código de pandas 1.x y 2.x, así que suelen escribir
`inplace=True`, asignaciones encadenadas, `resample("M")` o `df.append`. Indícale la versión
(«pandas 3.0, Copy-on-Write») y pídele que no use patrones obsoletos. Tras generar una cadena, exige
que añada `validate=` en cada `merge` y **compara la cifra con una consulta SQL independiente**,
como en la sección anterior. Si el asistente no sabe qué relación tiene cada unión, no puede saber si
suma bien.
